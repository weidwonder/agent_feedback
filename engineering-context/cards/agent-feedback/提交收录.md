# 业务域卡 — agent-feedback › 提交收录

## 职责
收下宿主 skill 内提交脚本发来的一次提交（1–5 条问题），按固定顺序把关后事务落库；并负责拒收计数、6 个月到期清理与每日备份。

## 权威实现与对外接口

| 能力 / 入口 | 权威实现（cite） | 类型 | 版本 / 状态 | 调用方 / 触发源 | 约束 |
|---|---|---|---|---|---|
| 字段契约与校验 | `packages/shared/src/validate.ts#validateSubmission` | 内部 | canonical | 服务端收录、提交脚本 | 遇第一个错误即返回；未知字段一律拒绝；字符串先 trim、按码点计长 |
| 长度、条数、枚举取值 | `packages/shared/src/limits.ts#LIMITS` | 内部 | canonical | 校验、登记、管理界面 | 请求体上限也在这里（`maxBodyBytes`），各处读它而不是另写数字 |
| 错误码全集 | `packages/shared/src/codes.ts#ERROR_CODES` | 内部 | canonical | 服务端响应 | 新增拒收原因先加这里 |
| 提交把关与落库 | `packages/server/src/routes/submissions.ts#registerSubmissionRoutes` | HTTP | POST /v1/submissions | 提交脚本 | 顺序固定：读体 → 来源地址限额 → JSON → 校验 → 登记状态 → 全站限额并落库；成功 201 |
| 计数与拒收统计 | `packages/server/src/counters.ts#bumpCounter` | 内部 | canonical | 提交、管理登录 | 只存计数不存内容；来源地址在读体后、解析前就计一次，超大或畸形请求同样占额度 |
| 到期清理 | `packages/server/src/jobs.ts#purgeExpired` | 定时 | 每小时 | 启动与定时器 | 收录满 6 个日历月的提交连同反馈整体删；计数保留 30 天 |
| 每日备份 | `packages/server/src/jobs.ts#backupIfDue` | 定时 | 每分钟检查 | 定时器 | 北京时间 03:00 后当天首份；只留 7 天 |
| 删除编号日志 | `packages/server/src/deletions.ts#applyDeletionLog` | 内部 | canonical | 启动与每小时维护 | 日志在库外、只追加、不进备份；恢复旧备份后靠它重删 |

## 陷阱项
- 在 server、module 或管理界面另写字段长度、枚举、必填判断 — 与 `packages/shared/src/validate.ts#validateSubmission` 迟早分叉，改用 shared 导出的校验与 `LIMITS`
- 用 `MAX(id)+1` 或复用编号 — `feedback` 与 `submissions` 靠 AUTOINCREMENT 保证编号永不复用，否则删除日志重放会误删新反馈，见 `packages/server/src/db.ts#openDb`
- 在事务外判全站上限 — 并发会超额，全站计数必须在 `packages/server/src/db.ts#withTransaction` 内先读后写
- 保存拒收内容用于排查 — 拒收只按天按原因计数，不落内容，这是隐私承诺的一部分
- 删除反馈时先删行后写日志 — `packages/server/src/deletions.ts#deleteFeedback` 必须先写库外日志再删行，日志写失败则不删
