# 业务域卡 — agent-feedback › 登记

## 职责
维护"允许提交的 skill 名单"：现名、改名后的旧名、启用与停用；注入工具与管理界面是它的两个写入方。

## 权威实现与对外接口

| 能力 / 入口 | 权威实现（cite） | 类型 | 版本 / 状态 | 调用方 / 触发源 | 约束 |
|---|---|---|---|---|---|
| 检查名称状态 | `packages/server/src/routes/registry.ts#registerRegistryRoutes` | HTTP | GET /v1/registry/check | 注入工具 | 登记令牌；名称先过 `validateSkillName`，不合法回 400 invalid_field；返回 registered / old_name / unknown 三态，旧名只回指现名，不放行 |
| 登记新名称 | `packages/server/src/routes/registry.ts#registerRegistryRoutes` | HTTP | POST /v1/registry | 注入工具 | 幂等：已存在返回 created=false；是旧名返回 409 old_name；新登记默认启用 |
| 现名查找 | `packages/server/src/db.ts#findSkillByName` | 内部 | canonical | 收录、登记 | 收录按现名精确匹配，旧名提交会被当作未登记拒收 |
| 名称校验 | `packages/shared/src/skill-name.ts#validateSkillName` | 内部 | canonical | 登记与检查接口、管理界面改名、注入工具 | 去首尾空白、非空、码点数不超过 `LIMITS` 上限；各调用方不得另写 |
| 改名与启停 | `packages/server/src/admin/skills.ts#renameSkill` | 内部 | canonical | 管理界面 | 事务内把原名写入旧名表；新名不得等于他人现名或旧名，可改回自己的旧名 |

## 陷阱项
- 用旧名提交或登记 — 旧名不再放行，`old_name` 只用来提示改用现名，改用 `packages/server/src/routes/registry.ts#registerRegistryRoutes` 返回的 `currentName`
- 在路由、管理界面或注入工具里另写名称校验（去空白、判空、长度上限） — 一律调用 `packages/shared/src/skill-name.ts#validateSkillName`
- 把停用当删除 — 停用后已收录的反馈保留且可查，只是不再收新提交，见 `packages/server/src/admin/skills.ts#toggleSkill`
- 手写 SQL 改 `skills.name` — 会漏写旧名表，改名只走 `packages/server/src/admin/skills.ts#renameSkill`
