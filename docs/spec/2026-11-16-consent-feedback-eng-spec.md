# agent-feedback_技术 Spec — 反馈前征得使用者同意、来源地址限额调到每天 50 次

> 变更 spec。现行契约的唯一出处仍是 `docs/spec/2026-09-29-agent-feedback-eng-spec.md`，本次落地时就地改写那份文档的相关条目（见 §1 末的同步清单），本文只描述这次改了什么、为什么、怎么验收。

## 0. 阅读导引

- **一句话目的**：使用宿主 skill 的 agent 发现 skill 本身出了问题时，不再静默提交，而是在当轮回复里列出问题、说明会去掉敏感信息、请使用者同意，同意后才提交并一句话告知结果；服务端每个来源地址每天的提交上限默认从 5 次调到 50 次。
- **端到端场景**：
  1. 使用者让 agent 用宿主 skill 导出报告，skill 写的命令不存在，agent 换方式完成。agent 在这一轮的回复里先交付报告，再在末尾列出"文档提到的导出命令不存在：……"，说明发送前会去掉敏感信息，问能否反馈给开发者。使用者回"可以"，agent 在下一轮提交，回复"已反馈给开发者"。
  2. 同一场景里使用者回"不用了"或没有理会、继续提别的需求：agent 不提交，本会话不再就这条问题询问。
  3. 一轮里出现 3 个问题，使用者回"只发第一条"：agent 只提交第一条。
  4. 使用者同意后提交，服务连不上：agent 回复一句"反馈没有发出去（服务暂时连不上）"，不重试。
  5. 使用者设了 `AGENT_FEEDBACK_DISABLED=1`：agent 不询问、不提交、不提及反馈。
- **核心流程图**：
  ```mermaid
  flowchart TD
    A[本轮发现宿主 skill 的问题] --> B{关闭开关?}
    B -->|是| X[什么都不做]
    B -->|否| C{属于何时反馈 且 不属于何时不反馈?}
    C -->|否| X
    C -->|是| D[照常完成本轮回复, 末尾列出问题标题与概要, 说明会去敏, 询问是否同意]
    D --> E{使用者回应}
    E -->|明确同意全部或部分| F[只提交同意的那几条]
    E -->|拒绝 / 未回应 / 答非所问| G[不提交, 这几条本会话不再询问]
    E -->|要求别再问或别再反馈| H[本会话不再询问与提交]
    F --> I[一句话告知成功或失败]
  ```
- **决策表**：
  | 输入 / 状态 | 条件 | 走向 | 结果 |
  |---|---|---|---|
  | 发现可报问题 | 本会话已提交 2 次 | 不询问 | 无 |
  | 发现可报问题 | 关闭开关为 1 | 不询问 | 无 |
  | 已询问 | 使用者明确同意 | 立即提交询问时列出的、被同意的条目 | 一句话告知结果 |
  | 已询问 | 拒绝、未回应、答非所问 | 不提交 | 这些条目本会话不再询问 |
  | 已同意并提交 | `invalid` | 按提示修正后重试一次 | 成败都一句话告知 |
  | 已同意并提交 | 其余失败原因 | 按 `FEEDBACK.md` 第 8、9 节处置（`node_too_old` 换运行环境后重调一次；漏外层结构的 `bad_input` 修正一次；`disabled` 按第 0 节停止且不提及）| 一句话告知结果，可附业务化原因；`disabled` 除外 |
  | 本会话已停止提交 | 第 8 节放弃、提交命令被拒、提交满 2 次 | 不再询问 | 无 |
  | 已询问 | 本会话已有一次拒绝或未回应 | 本会话不再询问 | 无 |

### 1.1 功能需求

| 编号 | 需求 |
|---|---|
| FR-001 | 关闭开关（第 0 节）不变：值为 `1` 时不记录、不起草、不询问、不安装、不提交、不提及反馈 |
| FR-002 | "何时反馈"5 种情形与"何时不反馈"情形不变；"本会话已提交满 2 次"后不再询问；本会话已停止提交（第 8 节放弃、提交命令被拒）后同样不再询问 |
| FR-003 | 询问时机：agent 在发现问题的那一轮回复里询问；问题导致任务中止时，在中止的那条回复里询问。询问附在回复末尾，本轮回复照常完成使用者的任务内容，询问不得中断、推迟或改变使用者的任务 |
| FR-004 | 同一轮里的多个问题合并为一次询问，最多 5 条，超过时按现有"取前 5"规则挑选 |
| FR-005 | 询问内容：逐条列出问题标题与一句话概要（遵守禁写清单），说明发送前会去掉所有敏感信息，问使用者是否同意把这些问题反馈给该 skill 的开发者；可指向 `PRIVACY.md` |
| FR-006 | 只有使用者明确同意才提交。部分同意只提交被同意的条目。拒绝、没有回应、答非所问都按不同意处理：这些条目不提交，且本会话不再询问任何问题（拍板人 2026-11-17 选定）。是否"明确同意"由 agent 按对话理解判断，不另设判据；向 agent 发出任务的上游程序代为回复同意，同样算同意（拍板人 2026-11-17 选定） |
| FR-007 | 使用者要求不要再问或不要再反馈：本会话不再询问、不再提交 |
| FR-008 | 提交的条目不得超出询问时列出并被同意的范围，内容须与询问时的概要一致；同意后在同一轮立即提交 |
| FR-009 | 提交后用一句话告知结果：成功说已反馈；失败说没有发出去，可附一句业务化原因（服务连不上、超出当日限额、该 skill 未开通反馈等），不贴原因码与输出原文；失败处理（`invalid` 修正重试一次、其余不重试、本会话不再提交）不变 |
| FR-010 | 删除"全程静默""不向使用者提及反馈""待报问题不写进使用者可见内容""任务收尾时一次性提交"的规则；使用者直接问起时如实回答的规则保留 |
| FR-011 | 提交命令被运行环境或使用者拒绝执行：放弃，本会话不再提交，一句话告知没有发出 |
| FR-012 | `PRIVACY.md` 改为：遇到 skill 本身的问题时，AI 助手被要求先列出问题、征得你同意后才发送（措辞如实反映这是对 AI 助手的要求，不是程序强制，拍板人 2026-11-17 选定）；删除"不会另行征求确认"；其余收集范围、保留期、关闭方式不变 |
| FR-013 | 服务端 `IP_DAILY_LIMIT` 未设置时默认 50；部署示例写 50；拒收提示文案仍按配置值动态生成 |
| FR-014 | §1 同步清单内的现行文档、卡片、评测场景与本 spec 一致，不残留"静默""不征求确认""每天 5 次"的现行口径（历史评审报告与已合并 PRD 不改） |
| FR-015 | 反馈模块版本号由 1.0.0 改为 1.1.0（拍板人 2026-11-17 指定），注入后宿主 `config.json` 的 `moduleVersion` 为 1.1.0 |
| FR-016 | 询问只陈述问题与发送范围，不劝说、不强调发送的好处、不反复请求 |

## 4. 核心逻辑

**4.1 `FEEDBACK.md` 结构调整**（写给 agent 的提示词，按 `dw-prose` 写现状、不写来历）：

- 开头一段：由"自主判断、自主起草、自主提交，不经使用者确认"改为"自主判断与起草，提交前征得使用者同意"。
- 第 1 节硬性规则：删静默、不提及、待报问题不可见三条；加"未经使用者明确同意不提交"；保留关闭开关、明确要求不反馈、命令被拒、每会话 2 次、禁写清单、如实回答。
- 第 4 节改名"何时询问、何时提交"：按 FR-003–FR-008 写；保留取前 5 规则与会话恢复规则。
- 新增询问话术样例一段（中文，使用者用其他语言时用使用者的语言），形如："另外，本次使用中我发现这个 skill 本身有 N 个问题：1.【标题】——【一句话概要】……发送前会去掉对话原文、路径、姓名、业务数据等所有敏感信息。可以把这些问题反馈给该 skill 的开发者吗？"
- 第 8 节处理结果：成功与失败都按 FR-009 一句话告知；表中"放弃"类动作不变；删"任何失败都不告知使用者"。
- 第 9 节运行环境：不变（安装时运行环境自己弹出的确认照旧）。
- 第 10 节例子：例 1 改为"当轮询问 → 同意 → 提交 → 告知"；新增拒绝、部分同意、未回应各一例；例 5 保留。

**4.2 `PRIVACY.md`**：开头段按 FR-012 改；"想知道发过什么"一节保留。

**4.3 服务端**：`IP_DAILY_LIMIT` 的默认值改为 50，校验下限仍为 1；部署示例同步。

**设计自检**：本次不引入新字段、新开关、新配置项。是否经同意只由 agent 规则保证，服务端无法验证；加"同意"字段只能证明 agent 声称同意，不能防伪，属于无需求对应的抽象，不做。

## 5. 错误处理

- 提交失败的分支与原因码处置不变，只把"不告知使用者"改为"一句话告知"（FR-009）。
- 询问后会话中断或上下文被压缩，找不到"使用者已同意"的记录：按未同意处理，不提交。

## 6. 安全 / 配置 / 不变量

```
Invariant 1: 未经使用者明确同意，agent 不发出提交请求
- 强制机制：FEEDBACK.md 硬性规则；上线评测逐场景检查提交是否只发生在同意之后。本闸门只是提示词约束，提交脚本与服务端无法验证同意；唯一的确定性兜底是运行环境对提交命令的审批，放开审批的环境里没有兜底。拍板人 2026-11-17 接受此限制
- 违反时：评测记为规则违反，挡上线
```

```
Invariant 2: 询问时展示给使用者的内容同样遵守禁写清单
- 强制机制：FEEDBACK.md 第 6 节适用范围扩到询问文字
- 违反时：评测按禁写出现计
```

配置 Cheat Sheet 变化：`IP_DAILY_LIMIT` int ≥ 1，非必填，默认 50，改后需重启。
