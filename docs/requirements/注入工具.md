# 注入工具

注入工具在维护者本机运行，一次完成三件事：把反馈模块放进宿主 skill、在宿主 skill 主说明里加引导语、在服务端登记该 skill。命令与退出码的契约见技术 spec `docs/spec/2026-09-29-agent-feedback-eng-spec.md` §3 与 §4.4，构建与使用步骤见 [部署与运维](../deploy.md)。上级：[REQUIREMENTS](../REQUIREMENTS.md)。

## 谁能用、对什么用

| 规则 | 说明 |
|---|---|
| 使用者 | 持有登记令牌的人（维护者，或维护者另外交给它登记令牌的维护 agent） |
| 注入对象 | MUST 是该 skill 的源头，即维护者开发和发布它的位置，由运行注入工具的人指定；MUST NOT 是本机安装后的副本（重装时会被整目录覆盖，且使用者拿不到）。注入后由维护者按该 skill 的正常方式发布 |

## 实例配置

- 注入前 MUST 先在注入工具里配置好线上服务实例的服务地址与登记令牌（登记令牌由管理界面生成）；未配置时拒绝注入并说明缺什么。
- 配置写在维护者本机的用户配置文件里，文件权限仅本人可读写；令牌从标准输入读取，不回显。
- 更换实例：实例地址变化后，配置新实例并对各宿主 skill 重新运行注入工具，即更新模块里的服务地址，并在新实例上登记；不迁移数据，新实例从零开始（重新登记、重新生成令牌）。

## 注入做什么

- 把反馈模块放入宿主 skill 的 `agent-feedback/` 子目录。
- 在宿主 skill 主说明末尾追加引导语：「skill反馈优化技能，请在用户skill处理不顺利、出错时候加载」，并指向该子目录里的规则文件；用标记行定位，重复运行不重复添加。
- 在服务端登记该 skill：新登记的为启用；已登记的不改变其启用或停用状态。
- 与实例相关的信息只写入服务地址和模块版本；登记令牌、查询令牌、管理密码 MUST NOT 写进宿主 skill 的任何文件。写完后工具扫描写出的全部文件，发现含登记令牌即回滚并失败。
- 模块自带忽略规则，装出来的运行环境不随宿主 skill 发布。

## skill 名称与前置检查

| 情况 | 表现 |
|---|---|
| 宿主 skill 未声明名称 | 报错并拒绝注入，不从目录名或其他信息推测 |
| 名称不合法 | 报错并拒绝，不写任何文件 |
| 声明的名称是某 skill 改名前的旧名 | 报错并拒绝，提示先把宿主 skill 的声明改成现名 |
| 源头已有模块、模块记录的服务地址就是当前配置的实例、但声明的名称不在该实例的登记名单中（改名未同步） | 报错并拒绝，提示先在管理界面把登记改成该名称 |
| 源头已有模块、但模块记录的是其他实例的地址 | 按更换实例处理，在当前实例新登记 |
| 指定目录下没有主说明文件 | 报错并提示指定 skill 源头目录 |

skill 名称 MUST 取宿主 skill 自己声明的名称。"已接入"以登记名单里的现名为准。

## 重复运行与已停用的 skill

- 宿主 skill 声明的名称已在登记名单中时，再运行一次等于把反馈模块升级到最新版；引导语不重复添加，登记不重复。
- 对已停用的 skill 重新注入只升级模块，不改变停用状态，并明确提示该 skill 已停用、需在管理界面启用。

## 失败与成功后的提示

- 三步要么全部完成，要么全部不做：写文件出错或登记失败时，宿主 skill 的文件恢复到注入前的样子（逐字节一致），命令以失败退出码结束，明确告知失败在哪一步、原因是什么，不静默。
- 成功后输出摘要（名称、新登记或已登记、启用状态、模块版本），并提示宿主 skill 所在仓库若有自己的流程要求（目录白名单、规范句去重、体积预算、变更记录等），由维护者按该仓库流程补充配套改动；这不属于注入工具的工作。

## 不做

- 不自动识别源头与安装副本，由运行的人指定目录。
- 不提供自动移除：从 skill 里撤下反馈模块由维护者手动完成。
