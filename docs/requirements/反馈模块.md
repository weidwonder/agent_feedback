# 反馈模块：agent 行为规则

反馈模块是嵌入宿主 skill 的 `agent-feedback/` 子目录。本文写 agent 与使用者能感知到的行为规则。规则的原文在 `packages/module/assets/FEEDBACK.md`（写给 agent），公开说明在 `packages/module/assets/PRIVACY.md`（写给使用者）；两者是提示词，规则以它们的现行文字为准，本文是需求侧的口径。提交内容的字段与长度限制见 [收集服务与把关](收集服务与把关.md)。上级：[REQUIREMENTS](../REQUIREMENTS.md)。

## 关闭开关

- 使用者在运行 agent 的环境里设置环境变量 `AGENT_FEEDBACK_DISABLED=1`，对所有带反馈模块的 skill 同时生效。
- 开关是 agent 的第一步检查，先于本模块的其他一切步骤：本会话不记录、不起草、不询问、不安装运行环境、不提交，也不发任何网络请求，并且不向使用者提及开关或反馈。
- 提交脚本自身在开关打开时同样不发请求。

## 何时反馈

任一情形命中，才记录为待反馈问题：

1. 宿主 skill 的同一个问题反复失败，换了做法仍然不行。
2. 宿主 skill 的指令与实际环境不符，例如它提到的命令、参数或位置不存在。
3. 宿主 skill 缺少一个使用者明显需要的能力。
4. 使用者明确表达对宿主 skill 的不满，或指出它有问题。
5. agent 按宿主 skill 执行后，自己发现结果是错的。

## 何时不反馈

- 使用者自己环境的问题，例如网络中断、缺少权限。
- 一次性的偶发失败。
- 与宿主 skill 无关的问题。
- 本会话已提交过同一个问题。例外：对该问题有了新信息，且本会话还有提交次数，可作为一次新提交追加，不修改已提交的内容；同一问题再次出现而尚未提交的，把出现次数计入该问题。
- 本会话已提交满 2 次。
- agent 不确定这是宿主 skill 的问题。拿不准时不提交。
- 使用者设置了关闭开关（见上）。
- 使用者要求不要再问或不要再反馈：本会话不再询问、不再提交；可简短应答；要求中带问句时按"直接问起"如实回答。

## 何时询问、何时提交

- **时机**：发现问题的那一轮回复照常完成使用者的任务内容，在回复末尾询问；问题导致任务中止时，在中止的回复末尾询问。询问不得中断、推迟或改变使用者的任务。
- **询问内容**：逐条列出标题与一句话概要，说明发送前会去掉所有敏感信息，询问是否同意反馈给该 skill 的开发者；可指向公开说明。
- **同意判定**：仅明确同意才提交，部分同意只提交被同意的条目；拒绝、未回应、答非所问均按不同意处理，这些条目不提交，本会话不再就它们询问。
- **提交范围与时机**：收到明确同意后在该轮立即提交，只包含询问时列出且被同意的条目，内容须与询问时的概要一致。
- **合并**：同一轮里的多个问题合并为一次询问，最多 5 条。超过 5 个时，按影响程度（阻断、绕过后完成、仅不便）取前 5 条；影响程度相同时，本会话出现次数多的优先，仍相同由 agent 挑选；其余不报。
- **会话上限**：每个会话最多提交 2 次，由 agent 自己数；服务端不按会话编号拒收。达到上限后不再询问。被服务拒收的提交、格式不合格的尝试、服务不可达的尝试都不占这 2 次。
- **会话编号**：同一会话首次提交时由提交脚本随机生成，后续提交沿用；不跨会话、不可回溯到个人。会话中断后恢复时，上下文里仍有已提交记录则沿用原会话编号与已提交次数，没有记录则按新会话处理。询问后会话中断或上下文被压缩，找不到使用者已同意的记录时，按未同意处理，不提交。
- 提交内容由 agent 与提交脚本共同提供，字段清单见 [收集服务与把关](收集服务与把关.md)。提交时间、操作系统、宿主 skill 名称与版本、反馈模块版本由提交脚本自动记录，agent 不填。宿主 skill 版本只读取宿主 skill 声明里附加信息中的版本一项，其他写法视为未声明，提交不带版本。

## 征得同意与如实回答

- 未经使用者明确同意不提交；提交后一句话告知成功或失败，可附业务化原因，不贴原因码与输出原文。
- 使用者直接问起（例如问是不是发了反馈）时，agent 不否认、不隐瞒：
  - 确定本会话没提交过，才说没有；
  - 发过的，如实说明发过哪些内容；
  - 已记下但尚未提交的，如实说明有哪些待报问题；
  - 上下文里找不到记录又不能排除提交过（例如上下文已被压缩），如实说明可能提交过，并指向同目录下的公开说明。
- 提交命令被运行环境或使用者拒绝执行：放弃，本会话不再提交，一句话告知没有发出去。

## 提交结果的处理

| 结果 | agent 怎么做 |
|---|---|
| 成功 | 记下会话编号与已提交次数，一句话告知已反馈给开发者 |
| 格式不合格 | 按返回的说明（哪一项、限制是多少）修正后最多重试一次；重试仍失败即放弃，本会话不再提交 |
| 被服务拒收（未登记、已停用、超限额等） | 放弃，不重试，不因说明改写后再交；本会话不再提交 |
| 服务连不上或超时 | 放弃，不暂存、不重试；本会话不再提交 |
| 开关已关闭 | 放弃，本会话不再提交 |
| 模块自身的问题（配置缺失、宿主声明读不到、输入结构不对等） | 放弃，本会话不再提交；仅在明显漏了外层结构时修正后重试一次 |

处理完允许的修正或运行环境重调后，用一句话告知最终成功或失败；失败可说明服务连不上、超出当日限额或该 skill 未开通反馈，不贴原因码与输出原文，不影响使用者任务。开关已关闭时停止一切反馈行为，不提及反馈。提交脚本恒以成功退出码结束、不向标准错误输出。

## 运行环境

- 提交脚本需要 Node 20 或更高版本。找不到时，agent 先在本机查找（系统 Node、宿主目录内已装出的运行环境）；仍找不到则尝试安装一次，只装进模块自己目录下的运行环境子目录，不改变使用者的系统环境（不装全局包、不改环境变量、不用包管理器）；校验和须与官方发布的校验和一致。安装步骤与固定版本见 `packages/module/assets/FEEDBACK.md` 第 9 节。
- 安装失败、校验失败、使用者或沙箱拒绝联网或写入，放弃本次提交，本会话不再尝试安装或提交。环境禁止联网时，提交同样视为失败。
- 装出来的运行环境不随宿主 skill 发布（模块自带忽略规则）。

## 禁写清单

询问文字与提交内容的每个字段都不得出现：对话原文、代码片段、报错原文、凭据与密钥、文件路径、使用者或第三方的姓名、公司与项目的内部名称、任何可识别到个人的信息，以及使用者业务内容的原样（如金额、单据或工单编号、工单标题与正文、被处理文件的内容）。agent 只写宿主 skill 出的问题，用自己的话概括现象；说明问题需要业务背景时只写脱敏后的概括，不写具体数值、编号与原文，与问题无关的业务背景不写；拿不准某段信息是否可识别，就改写得更概括或整条不报。

skill 名称本身（宿主 skill 与相关 skill 清单里的名称）不受此限；skill 描述里仍不得出现公司或项目的内部名称。服务端不检查内容是否含禁写信息，靠这份清单与上线评测把关。

## 公开说明

模块里的公开说明面向使用者，写明：先列出问题并征得使用者明确同意后才发送，支持部分同意，拒绝、未回应或答非所问的条目不提交且本会话不再询问，提交后一句话告知结果；收集哪些信息；不收集什么；每条反馈保存 6 个月，到期自动删除，也可被维护者提前删除；到期或被删除后备份里的副本最多再留 7 天；按网络地址统计的当日提交次数只用于限额，30 天后删除；反馈只供维护者了解问题、改进 skill，不用于训练或改进任何智能模型；如何用开关关闭；如何询问 agent 发过什么。

## 宿主 skill 的原有内容不变

宿主 skill 的原有说明、能力、触发方式除新增反馈模块子目录和一句引导语外一字不改（写入方式见 [注入工具](注入工具.md)）。
