# 收集服务与把关

收集服务公开接收提交，按登记名单、字段规则和限额把关，保存反馈并每天备份。字段定义、拒收码、接口与环境变量的契约只在技术 spec `docs/spec/2026-09-29-agent-feedback-eng-spec.md` 的 §2.1、§3、§6，本文写用户可感知的规则。日与月的边界一律按北京时间；字符数按字计，中英文字符均计为 1。上级：[REQUIREMENTS](../REQUIREMENTS.md)。

## 提交的内容

每次提交由会话部分（一份）与问题部分（1 至 5 条）组成。

**会话部分**

| 信息项 | 规则 | 提供者 |
|---|---|---|
| 提交时间 | 必填 | 提交脚本自动记录 |
| 宿主 skill 名称 | 必填；须已登记且启用 | 提交脚本读取宿主 skill 的声明 |
| 宿主 skill 版本 | 可选；只读取宿主声明附加信息里的版本一项 | 提交脚本 |
| 反馈模块版本 | 必填 | 提交脚本 |
| 会话编号 | 必填；随机生成，只用于识别同一会话的多次提交，不做归并 | 提交脚本生成，agent 后续沿用 |
| 任务概要 | 必填；≤ 50 字；不含姓名、公司名、项目名 | agent |
| 用户信息 | 必填；使用者的角色或大致画像，≤ 50 字 | agent |
| 用户信息来源 | 必填；已知 或 猜测 | agent |
| 操作系统类型 | 必填 | 提交脚本自动读取 |
| agent 名称 | 必填；≤ 100 字 | agent |
| agent 版本 | 可选；≤ 50 字 | agent |
| 运行环境名称 | 必填；agent 所在运行环境，如 Claude Code；≤ 100 字 | agent |
| 运行环境版本 | 可选；≤ 50 字 | agent |
| 相关 skill 清单 | 0 至 10 项；每项为名称（≤ 100 字）加描述（≤ 50 字） | agent 按语义判断 |

**问题部分**

| 信息项 | 规则 |
|---|---|
| 问题标题 | 必填；≤ 30 字 |
| 详细描述 | 必填；≤ 1000 字；实际发生了什么、期望是什么、已尝试了什么 |
| 反馈类型 | 必填；缺陷 / 使用摩擦 / 缺能力 / 建议 |
| 影响程度 | 必填；阻断 / 绕过后完成 / 仅不便 |
| 是否已解决 | 必填；本会话里是否已绕过或解决 |
| 推荐解法 | 已解决时必填，≤ 500 字；未解决时必须为空；违反按格式不合格拒收 |
| 本会话出现次数 | 必填；整数，1 至 1000 |

除上表字段外的任何多余字段一律拒收，避免把禁写内容塞进自造字段。

**服务端补充（每条问题）**：反馈编号（`FB-` 加序号，如 `FB-0012`，永不复用）、收录时间、处理状态。

## 把关规则

| 规则 | 表现 |
|---|---|
| 登记名单 | 只收录已登记且启用的宿主 skill 的提交；未登记、已停用或使用旧名的提交不保存。名称完全一致才算匹配，区分大小写，不做模糊匹配 |
| 字段校验 | 缺项、超长、取值不在可选范围、条数为 0 或多于 5 条、出现多余字段时拒收，并返回说明：哪一项、限制是多少 |
| 请求体大小 | 请求体超过 64 KiB 拒收，按格式不合格计 |
| 来源地址限额 | 同一网络地址（IP）每个自然日默认最多 50 次提交请求（可由维护者配置），所有请求都计入，含被拒收的；共用出口地址的多人共用这份额度 |
| 单次上限 | 一次提交最多 5 条问题；超过按格式不合格拒收，agent 可删减后重试 |
| 全站限额 | 全站每个自然日最多收录 500 次提交，只计收录成功的，被拒收的不计；限额数值在服务端配置中调整，界面不提供 |
| 拒收记录 | 只记录全站的拒收次数与原因（超出限额、未登记或已停用、格式不合格），按天统计，不按 skill 区分，不保存被拒收的内容 |
| 提交方看到什么 | 服务对提交方只返回收录结果（含反馈编号）或拒收原因，不返回任何已存的反馈 |
| 收录时效 | 通过把关后同步写入，收录后即可在管理界面与查询通道查到 |

## 登记名单的口径

- 新登记的 skill 为启用；停用后之后的提交不保存，历史反馈保留到期满；重新启用后不补收停用期间的提交。
- 改名后，该 skill 的全部历史反馈归到新名称下；此后以旧名称提交的反馈不再收录；使用者更新到声明新名称的宿主 skill 版本后恢复收录。改名的操作与限制见 [管理界面](管理界面.md)。
- 登记只能由注入工具（凭登记令牌）新增，见 [注入工具](注入工具.md)。

## 处理状态

待处理 / 有效 / 无效 / 重复 / 已处理，共五种，默认待处理；五种之间可任意互改。维护者与维护 agent 对同一条反馈改状态时以最后一次修改为准；重复写同一状态无副作用。

## 保留、删除与备份

- 反馈保存满 6 个月（按收录时间）后自动删除，之后界面与查询通道均查不到。
- 维护者可提前删除单条反馈，删除后不可恢复；服务只保留被删反馈的编号（不保留内容），用于从备份恢复后重新删除，被删编号在任何时候都不会重新可查。
- 每天北京时间 03:00 备份一次，只保留最近 7 份；反馈到期或被删除后，其副本在备份里最多再留 7 天。服务故障恢复时最多丢失不到一天的数据。
- 按网络地址统计的当日提交次数只用于限额，30 天后删除，不与反馈内容关联。
- 服务提供健康检查地址，供维护者配置的外部可用性探测使用。

## 不做

服务端不检查内容是否含敏感信息，不做任何自动处理（自动回复、分类、归并、交给智能能力）。见 [REQUIREMENTS](../REQUIREMENTS.md) 的明确不做。
