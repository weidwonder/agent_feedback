# 注入：把反馈模块放进 skill 源头

> 读取条件：维护者要求给某个 skill 源头接入或升级反馈模块（注入）时读。前置：注入 MUST 由维护者发起；实例未配置时维护者已把登记令牌交给你（本机 config 已就绪则无需）。

## 定位与前置判定

- 注入 = 把 `agent-feedback/` 反馈模块写进 skill 源头目录、在 `SKILL.md` 末尾追加一句引导语、并在收集服务上登记该 skill 名称。
- 注入对象 MUST 是 skill 的**源头目录**（维护者仓库里含 `SKILL.md` 的那份源码）；MUST NOT 对 `~/.claude/skills/` 等安装副本注入——安装器重装时整目录覆盖，注入内容随之丢失。分不清哪个是源头时问维护者。
- skill 名称由宿主 `SKILL.md` 的 frontmatter `name` 声明；宿主没声明 `name` 时工具直接拒绝，MUST NOT 从目录名推断，让维护者先在宿主里声明。
- 登记令牌只存在本机配置（权限 0600），MUST NOT 写进宿主目录、日志或反馈内容。

## 步骤

1. 定位 agent_feedback 仓库（取法见 SKILL.md「开始前」）。
2. 构建（产物已存在且维护者没要求升级工具时可跳过；Node ≥ 22.18）：

   ```sh
   cd <agent_feedback 仓库>
   npm install
   npm run build
   ```

   产物是 `packages/injector/dist/agent-feedback.mjs`；`npm run build` 会同时构建反馈模块（缺 `packages/module/dist/submit.mjs` 时注入会报错要求先构建）。
3. 配置实例（首次使用或实例地址变更时才做；登记令牌从标准输入读）：

   登记令牌 MUST NOT 以字面量出现在命令行（会进会话记录与进程列表）：把维护者交付的令牌用写文件的方式写进一个 0600 临时文件，再喂给工具，用完删除。

   ```sh
   cd <agent_feedback 仓库>
   node packages/injector/dist/agent-feedback.mjs config --endpoint <服务地址> < <登记令牌临时文件>
   ```

   PowerShell 不支持 `<` 重定向，用 `Get-Content <临时文件> | node …`；维护者本人在终端运行时也可直接交互输入（TTY 下不回显）。配置写入本机 `~/.config/agent-feedback/config.json`（Windows 为 `%APPDATA%\agent-feedback\config.json`），权限 0600。

   注意 `AGENT_FEEDBACK_ENDPOINT` 只作用于你自己发起的请求与这条命令的 `--endpoint` 实参；注入工具运行时只读本机 config.json，实例地址变更后 MUST 重跑本步。
4. 注入：

   ```sh
   cd <agent_feedback 仓库>
   node packages/injector/dist/agent-feedback.mjs inject <skill 源头目录>
   ```

   工具从自身位置定位反馈模块模板，MUST 在仓库构建布局内运行（或用 `--module-dir <目录>` 显式指定模块包目录）。
5. 完成后按宿主仓库自己的流程补配套改动（目录白名单、规范句去重、体积预算、变更记录）——工具完成时会打印这条提示。这些门禁的判据在宿主仓库，不在本 skill。

## 结果与异常处置

| 症状 | 原因 | 解法 |
|---|---|---|
| 重复运行 inject，目录内容被覆盖、引导语仍只有一句 | 重复注入是升级：模块文件覆盖为当前版本 | 正常，无需处理 |
| 命令以退出码 1 结束，宿主目录恢复到注入前 | 任一步失败（登记失败、写文件出错）整体回滚 | 按错误信息修正后重试；MUST NOT 手工补写回滚掉的一半 |
| 报「X 是 Y 改名前的旧名；先把宿主声明改成现名」 | 宿主 frontmatter 声明的名称是服务上登记现名的旧名 | 先把宿主 `name` 改成现名，再重新注入 |
| 报「该源头已接入当前实例，但名称 X 不在登记名单中」 | 同一服务地址上重建过实例（已知风险） | 交维护者按报错在管理界面把登记改成该名称，或按 `docs/TODO.md` 已知风险节换服务地址；MUST NOT 绕过 |
| 该 skill 已停用 | 服务端登记存在但被停用 | 提示维护者到管理界面启用，注入流程照常完成 |

## 案例

维护者说「给 note-keeper 的源头接上反馈通道」。确认 `~/projects/skills/note-keeper` 是源头目录（`~/.claude/skills/note-keeper` 是安装副本，不注入），维护者在会话里交给你登记令牌。构建 → `printf '%s' '<登记令牌>' | node packages/injector/dist/agent-feedback.mjs config --endpoint https://fb.weid.fun` → `node packages/injector/dist/agent-feedback.mjs inject ~/projects/skills/note-keeper`。目录多出 `agent-feedback/`，`SKILL.md` 末尾多一句引导语，服务登记了 note-keeper。之后按 note-keeper 仓库的流程把 `agent-feedback/` 加进交付白名单并写它的变更记录。
